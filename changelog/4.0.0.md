# Core 4.0.0

El Core deja de copiarse en cada proyecto: pasa a su propio repositorio,
[`SM-SOLUCIONES/sm-core-maven`](https://github.com/SM-SOLUCIONES/sm-core-maven), y se publica como repositorio Maven
público en `https://sm-soluciones.github.io/sm-core-maven`. Implementa el
[ADR 0006](https://github.com/SM-SOLUCIONES/sm-template/blob/main/backend-v2/docs/adr/0006-core-publicado-como-artefacto.md).

Es major por dos motivos: el directorio `core/` desaparece de los proyectos, y `core-protocolo-jwt` deja de tener un
`jwt.secreto` por defecto. No cambia ningún endpoint, DTO, permiso ni tabla.

## Qué cambia

- **Repositorio propio.** Los módulos `core-*` y `core-parent` viven en la raíz de `sm-core-maven` (sin la carpeta
  `core/`). Cada módulo conserva su documentación de implementación (`core-crud/docs/`, `core-kernel/docs/`,
  `core-protocolo-sso/docs/`), y el historial de versiones queda en `changelog/`.
- **Publicación.** Un tag `v{version}` corre el workflow `publicar.yml`: verifica que el tag coincida con la versión,
  corre los tests y publica `core-parent` y todos los módulos (con su jar de fuentes) en GitHub Pages. No hace falta
  token para descargarlo. Una versión publicada no se vuelve a publicar.
- **Documentación general.** Reglas, arquitectura, auditoría, criterios, servicios y ADRs (lo que era `core/docs/`)
  dejan de ser parte del Core: pasan a `docs/` de cada proyecto. El template (`sm-template/backend-v2/docs/`) es la
  referencia.
- **Integridad.** `core/integridad.py`, `core/integridad.sha256` e `IntegridadDelCoreTest` se eliminan: el proyecto ya no
  tiene el código del Core, así que no lo puede modificar. CORE-01 del checklist pasa a verificar que el proyecto
  consume el Core publicado (sin `core/` copiado ni módulos `core-*` propios).
- **`jwt.secreto` obligatoria.** `AuthJwtService` ya no tiene un secreto por defecto: el código del Core es público y
  cualquiera podría firmar tokens válidos con él. Si el proyecto declara `core-protocolo-jwt` sin `jwt.secreto`, el
  arranque se corta con `IllegalStateException` nombrando la propiedad.

## Cómo actualizar un proyecto (desde 3.7.0)

1. Mover `core/docs/*` a `docs/` (y `core/docs/README.md`, el negocio del proyecto, a `docs/README.md`), y reemplazar
   en el proyecto las rutas `core/docs/` por `docs/` (`CLAUDE.md`, `README.md`, `.claude/commands/*.md`,
   `docs/excepciones.md`, comentarios de `app/`). Los links a la documentación de un módulo
   (`core/core-crud/docs/...`) pasan a `https://github.com/SM-SOLUCIONES/sm-core-maven/blob/main/core-crud/docs/...`.
   Copiar del template las versiones actualizadas de `docs/rules/versionado.md`, `docs/arquitectura/core/README.md`,
   `docs/auditoria/` y `docs/adr/0006-*`.
2. Borrar `core/` entero y `app/src/test/java/com/blue/open/IntegridadDelCoreTest.java`.
3. `pom.xml` raíz: deja de ser `core-parent` y pasa a ser un agregador sin parent con un único `<module>app</module>`.
   Copiarlo del template.
4. `app/pom.xml`: el `<parent>` pasa a `com.blue.open:core-parent:4.0.0` con `<relativePath/>`, y se agrega el
   `<repositories>` con `https://sm-soluciones.github.io/sm-core-maven` (copiarlo del template). Las dependencias `core-*`
   no cambian: siguen sin `<version>`.
5. Si el proyecto usa `core-protocolo-jwt`: verificar que `jwt.secreto` esté definida en todos los
   `application.*.properties` y en los perfiles de test. Conservar el valor que ya tenía para que los JWT emitidos
   sigan validando.
6. Deploy: actualizar desde el template las plantillas `deploy/plantillas/spring-3.9-java-25*/Dockerfile` (ya no copian
   `core/`) y `.dockerignore`.
7. Correr `mvn -pl app test` y commitear `docs/api` si cambió.
