# Core 2.2.0

## Resumen

Se elimina la inyección por campo (`@Autowired` sobre un atributo) de todo el repositorio. Las clases concretas reciben sus dependencias por constructor (`private final` + `@RequiredArgsConstructor`); las clases base que extienden los proyectos las reciben por setter público, para que ninguna subclase tenga que declarar un constructor ni encadenar `super(...)`.

La regla queda escrita en [`docs/rules/inyeccion-de-dependencias.md`](https://github.com/SM-SOLUCIONES/sm-template/blob/main/backend-v2/docs/rules/inyeccion-de-dependencias.md), enlazada desde `AGENTS.md`.

Es **minor** aunque toca dos APIs puntuales (`ThymeleafUtil` y el constructor de `AuthService`). Un proyecto que solo extiende las clases base del Core no necesita tocar nada.

## Cambios

- **Clases base → inyección por setter** (`core-crud`, `core-identity`, `core-multiempresa`): `AbstractService`, `AbstractController`, `BaseUserService`, `BaseUserController`, `BaseRoleService`, `BaseUserServiceMultiempresa`, `BaseCompanyService`, `BaseRoleServiceMultiempresa` y `BaseUserMultiempresaMapper` exponen ahora un setter `public` anotado con `@Autowired` por dependencia. Los campos siguen siendo `protected` y con el mismo nombre: el código de las subclases no cambia.
- **Clases concretas → inyección por constructor**: el resto de los beans del Core y de `Code` declaran sus dependencias como `private final` con `@RequiredArgsConstructor`.
- **Dependencias opcionales → `ObjectProvider`**: se reemplazó `@Autowired(required = false)` por `ObjectProvider<T>` + `getIfAvailable()` en `ExecutionTraceAspect` y `RequestLoggingFilter` (`core-kernel`), y en `AuthService.estrategias` (`core-identity`), que además puede estar vacío si el proyecto no declara ningún módulo `core-protocolo-*`.
- **`lombok.config` en la raíz del reactor**: declara `@Lazy`, `@Qualifier` y `@Value` como anotaciones copiables. Sin eso, `@RequiredArgsConstructor` genera el constructor sin ellas y Spring no resuelve el ciclo `AuthService → ContextoDeEmpresa → AuthService`.
- **`ThymeleafUtil`** (`core-kernel`): `templateEngine` era un campo `static` anotado con `@Autowired`, algo que Spring nunca inyecta (quedaba siempre en `null`). Pasa a ser un bean normal con el motor por constructor y `getProcessedHtml(...)` deja de ser `static`.
- **Tests**: los unitarios construyen la clase con `new` pasando los mocks al constructor, o llamando a los setters cuando prueban una clase base. `ReflectionTestUtils.setField` queda solo para los campos `@Value`.

## Migración

Para un proyecto que usa el Core sin modificarlo, no hay nada que hacer: las clases base siguen exponiendo los mismos campos `protected` con los mismos nombres.

- **`ThymeleafUtil`**: si el proyecto llamaba `ThymeleafUtil.getProcessedHtml(...)` de forma estática, ahora se inyecta el bean y se llama sobre la instancia. (En la práctica no había llamadas posibles: el `TemplateEngine` estático nunca se inyectaba.)
- **`AuthService`**: ya no tiene constructor sin argumentos y `estrategias` pasó de `List<EstrategiaDeAutenticacion>` a `ObjectProvider<EstrategiaDeAutenticacion>`. Solo afecta a código que lo instancie a mano (por ejemplo un test viejo): como bean de Spring se resuelve solo.
- **Código propio del proyecto**: pasar los `@Autowired` de campo a constructor según [`docs/rules/inyeccion-de-dependencias.md`](https://github.com/SM-SOLUCIONES/sm-template/blob/main/backend-v2/docs/rules/inyeccion-de-dependencias.md). No es obligatorio para que compile —la inyección por campo sigue funcionando en Spring— pero sí lo es por regla del repositorio.
- **`lombok.config`**: si el proyecto vive fuera de este reactor, copiar el archivo de la raíz. Sin él, un `@Lazy` o un `@Qualifier` sobre un campo `final` se pierde al generar el constructor.
